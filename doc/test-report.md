### 缺陷详情（Top 3，修复前现场记录）

**D-01 身份完全由请求头决定（Critical）**

```text
客户端 → X-Synetra-User: admin → current_user() → store.get_user("admin") → role=admin
```

任何能访问 8000 端口的进程/脚本，只需一个请求头即可执行用户管理、AI 配置、任务删除等全部管理员操作；前端 `localStorage["synetra.session"]` 也只是明文 `{username, role}`，不参与鉴权。若当前阶段定位为「本地单用户演示」可接受，但**上线前必须替换为签名 token / 会话**，否则等同无权限系统。

**D-02/D-04 鉴权覆盖不一致（Major）**

| 路由 | 鉴权现状 |
| --- | --- |
| `POST /api/connections` | ❌ 无依赖（匿名可建） |
| `PUT /api/connections/{k}` | ❌ 无依赖 |
| `DELETE /api/connections/{k}` | ✅ `DeveloperDep` |
| `GET /api/tasks`、`/api/runs`、`/api/connections`、`/api/mdm/models` | ❌ 无依赖（匿名 200） |
| `/api/users*`、`/api/llm/*` | ✅ `AdminDep`（匿名 → 403） |

**D-03 API 连接无法带参数保存（Major）**

新建 API 连接时，只要点了「添加参数」或「添加 Header」，提交即 422，弹窗内提示「新建失败」。不含 params/headers 的 API 连接可正常保存（`CN-09` 通过），说明是 `meta` 类型约束与前端数据结构不匹配。

## 4. 正向验证亮点

以下能力本轮验证**行为正确**，可视为已有质量资产：

1. **只读查询守卫**：`DELETE FROM …` 被拒绝且源表数据未被破坏（`QR-05` 二次 COUNT 校验）。
2. **引用保护**：被任务引用的连接删除返回 409，并完整列出引用任务（`CN-07`）。
3. **管理员保护**：最后一名启用管理员不可降级/停用/删除（`SEC-06/07`）。
4. **XSS 防护**：连接名注入 `<img onerror=alert(1)>` 按纯文本展示、未执行、未注入 DOM（`NEG-02`）。
5. **未配置 LLM 的降级**：对话生成、任务字段 AI 生成、连通测试均给出可读错误而非白屏/500（`AI-02`、`TK-05`、`LLM-03`）。
6. **租户/角色可见性**：developer/readonly 侧边栏均隐藏「AI 管理」（11 → 10 项），权限页对非管理员显示「用户列表不可达」且无新建入口（`AUTH-07/08`、`SEC-09/11`）。
7. **数据一致性**：任务运行后目标库直查行数增量精确等于源表 25 行（`FLOW-02`）。
8. **画布持久化**：节点改名 + 批次大小改动在保存后同时通过「配置层 API」与「界面重开」双通道校验（`TK-17`）。

## 6. 未覆盖 / 建议补测

| 项 | 原因 | 建议 |
| --- | --- | --- |
| LLM 真实生成质量（草稿正确性、表达式正确性） | 无 DeepSeek API Key | 提供测试 Key 后补 3~5 条黄金用例（生成→核对→落库→运行） |
| SMTP 告警真实投递 | 无 SMTP 凭据 | 用 MailHog 本地收信验证阈值触发→发信→事件表 |
| 定时自动触发（cron 到点执行） | E2E 环境关闭本地调度器以保证确定性 | 单开一轮验证：短周期 cron + 等待 1 个周期，断言 run_record 新增 |
| 主机资源真实指标 | Windows 无 `/proc` | 在 Linux 容器内复跑 `MO-01/02` |
| 数据对账（checksum 比对） | 需开启对账，页面默认无记录 | 任务开启对账后验证「一致/差异」两种态 |
| API/CSV 源端到端抽取 | 受 D-03 阻塞（params 无法保存）；CSV 需真实文件 | 修复 D-03 后补 API 连接全链路 |
| 增量抽取水位推进 | 需多轮写入 + 水位回读 | 补 2 轮运行，校验 `task_watermark` 与增量行数 |
| 并发/性能 | 超出本轮范围 | 另立性能方案（50 并发 run、10 万行抽取） |

## 附录 B：本轮为稳定性所做的执行约束

| 现象 | 处理 |
| --- | --- |
| headed 模式下 106 条用例反复开关浏览器，桌面持续闪烁 | 默认改 headless；需要观察时 `E2E_HEADED=1` |
| Playwright 启动时清空 `outputDir`，被宿主 safe-delete 守卫（>500 文件）拦截导致整轮失败 | 每次运行使用独立时间戳目录 `reports/e2e/<RUN_ID>/` |
| `video` 依赖 ffmpeg 二进制（本机未装） | 关闭录屏，证据改用「每用例关键步骤全页截图」 |
| Windows 下 Playwright 用 GBK 解析子进程输出，后端中文日志触发解码异常 | 后端 webServer 输出不回传，可用性由 `/health` 探针保证 |
| 页面首帧为加载态（统计卡 0、列表「加载中…」、下拉「（无可用连接）」） | 统一改为 `expect.poll` / 定向选择器（如 `tr[title="点击查看运行详情"]`），不读首帧 |
| 前端无 `data-testid` | 选择器集中：`#login-user/#login-pass` > placeholder > `role=tab/button` > `title` 属性 > 中文文本，全程未改动任何 `src/` 业务代码 |
