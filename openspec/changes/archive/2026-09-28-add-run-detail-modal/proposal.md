# Proposal: 运行历史详情弹窗

## Why

总览页「最近运行历史」只以一行摘要展示运行实例（标识、任务、触发方式、状态、行数、时间），失败时无法看到失败原因、无从判断是数据源问题还是目标写入问题；后端其实已经提供了单次运行的详情与日志接口（`GET /runs/{run_id}`、`GET /runs/{run_id}/logs`），但前端没有任何入口消费它们，数据工程师排查一次失败只能去翻后端日志或数据库。缺少这层「点进去看」的能力，运行历史就只是一张不可深入的状态快照。

## What Changes

- **运行历史可点击查看详情**：总览页运行历史表格的每一行可点击（并提供行尾「详情」按钮作为显式入口），打开该次运行的详情弹窗。
- **详情弹窗内容**（全部复用既有接口，不新增后端端点）：
  - 运行基本信息：运行实例、任务标识、所属项目、状态、触发方式、开始时间、结束时间、耗时、尝试次数、写入行数；
  - 失败原因：失败运行显著展示 `error` 文本；
  - 任务上下文：经 `GET /tasks/{task_key}` 展示源连接、目标连接、源对象、目标对象、写入模式与调度信息；任务不可获取时降级提示，不阻塞其余内容；
  - 运行日志：经 `GET /runs/{run_id}/logs` 按时间顺序展示时间戳/级别/内容，空日志展示空状态。
- **运行中记录的动态刷新**：打开仍在运行的记录时，日志按游标增量轮询、运行状态同步刷新，运行结束后自动停止，关闭弹窗清理定时器。
- **加载与错误态**：详情加载中展示骨架/加载提示；详情或日志请求失败在弹窗内以 Callout 提示，并尽可能保留已有信息（列表行数据可作为首屏兜底）。

## Capabilities

### New Capabilities

- 无（本次不引入新能力，仅在既有监控能力内扩展运行历史的可深入程度）。

### Modified Capabilities

- `monitoring-reconciliation`: 「运行历史」需求扩展为支持点击单条运行记录查看详情；并新增「运行详情中的任务上下文」与「运行详情中的运行日志」两项需求，约束详情弹窗的内容组成与降级行为。

## Non-Goals（明确不做）

- 不新增后端端点、不修改运行/日志/任务的数据模型（`/runs/{run_id}`、`/runs/{run_id}/logs`、`/tasks/{task_key}` 已满足）。
- 不做日志实时推送（SSE/WebSocket），运行中仅按游标轮询。
- 不在详情内提供重跑、终止、删除、下载产物或数据抽样预览等操作。
- 不做对账与告警事件在运行详情内的关联展示（二者按 `task_key` 关联，非按 `run_id`）。
- 不改造 Monitor 页表格的行点击（如需复用详情组件，作为 P2 可选项记录在 tasks）。

## Impact

- 前端：`services/frontend/src/pages/Overview.jsx`（行点击与详情入口、弹窗挂载）；新增详情弹窗组件（如 `services/frontend/src/components/RunDetailModal.jsx`）；复用 `components/ui` 既有 `Modal / Badge / Callout / Skeleton` 与 `mac-detail__item` 等样式，不改动 UI 组件库契约。
- 后端：无改动，仅消费既有 `GET /api/runs/{run_id}`、`GET /api/runs/{run_id}/logs?since=`、`GET /api/tasks/{task_key}`。
- 数据/接口契约：无破坏性变更（**BREAKING**：无）。
