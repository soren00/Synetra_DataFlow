# Tasks: 运行历史详情弹窗

依赖说明：第 1 组为详情组件本体（不依赖页面），第 2 组为总览页接入，第 3 组为 P2 扩展。全部为前端改动，后端与数据模型不动；验证均在本地启动后端 + 前端后进行。

## 1. 详情弹窗组件（P1）

- [x] 1.1 [P1] 新增 `services/frontend/src/components/RunDetailModal.jsx`，接收 `{ run, onClose }`，用 `Modal` 搭建骨架，并在打开时立即用传入的行数据渲染「运行基本信息」首屏（运行实例、任务、所属项目、状态、触发方式、开始时间、结束时间、耗时、尝试次数、写入行数），键值对使用 `mac-detail__item / mac-detail__label / mac-detail__value`，状态用 `Badge` 复用 `STATE_TONE / STATE_CN`、触发方式复用 `TRIGGER_CN`。
  - 验证：在总览页点开任一运行记录，弹窗首屏无需等待接口即出现运行实例、任务、状态、开始时间与写入行数；`finished_at` 为空时结束时间与耗时显示为「进行中」占位。
- [x] 1.2 [P1] 打开弹窗后并行请求 `GET /runs/{run_id}` 覆盖首屏数据，并显著展示失败原因：`status === "failed"` 且 `error` 非空时，用 danger `Callout` 展示 `error` 全文（可换行、可选择）。
  - 验证：对一条失败运行打开详情，弹窗内出现 danger 样式的失败原因文本且内容与 `GET /api/runs/{run_id}` 返回的 `error` 一致；成功运行不出现该区块。
- [x] 1.3 [P1] 任务上下文区块：请求 `GET /tasks/{task_key}`，展示源连接、目标连接、源对象、目标对象、写入模式（append/upsert）与调度信息（cron、下次运行）；接口 404 或失败时该区块降级为 warning `Callout`（「任务配置不可获取（可能已被删除）」），不影响其余区域。
  - 验证：对一条任务仍存在的运行打开详情，能看到源/目标连接与对象、写入模式；手动删除该任务后再打开同一历史运行，任务上下文区显示降级提示，基本信息与日志照常展示。
- [x] 1.4 [P1] 运行日志区块：请求 `GET /runs/{run_id}/logs`，按时间顺序在固定高度的等宽滚动区展示 `时间戳 [级别] 内容`；日志为空时展示空状态；请求失败时展示 danger `Callout` 与「重试」按钮。
  - 验证：打开有日志的运行能看到按时间递增的日志行且区域内部滚动；打开无日志的运行显示暂无日志空状态；断网/后端不可达时日志区显示失败提示与重试按钮且基本信息仍可见。
- [x] 1.5 [P1] 运行中记录的刷新：以 `finished_at` 为空为主判据，每 3 秒用上次响应 `cursor` 作为 `since` 增量拉取日志并追加（不重排已有条目），同时刷新 `GET /runs/{run_id}`；`finished_at` 出现后停止轮询；弹窗关闭或组件卸载时清理定时器。
  - 验证：手动触发一次耗时任务并立即打开其详情，日志随执行持续追加且不重复、不跳动；运行结束后不再发起轮询（网络面板无新增请求）；关闭弹窗后定时器清理（再次打开不会出现双份追加）。

## 2. 总览页接入（P1）

- [x] 2.1 [P1] `services/frontend/src/pages/Overview.jsx` 增加「当前打开的 run」状态，运行历史表格整行可点击打开 `RunDetailModal`（行 hover 手型 + 轻量高亮），并在行尾增加 `eye` 图标按钮作为显式入口（按钮点击阻止冒泡避免重复触发）。
  - 验证：点击行任意位置或行尾详情按钮均打开同一条运行的详情弹窗且只打开一次；关闭弹窗后「全部/成功/失败」筛选状态与列表顺序保持不变。
- [x] 2.2 [P1] 详情弹窗与筛选栏共存的行为校验：筛选为「失败」时打开失败详情、关闭后仍停留在「失败」筛选；同时确认表格现有列与列宽不因新增操作列而错位。
  - 验证：切到「失败」筛选 → 打开一条失败运行详情 → 关闭，筛选仍为「失败」且列表条数不变；表头与数据列对齐无错位。
- [x] 2.3 [P1] 加载与错误态：详情接口请求中展示 `Skeleton`/加载提示；`GET /runs/{run_id}` 失败时弹窗顶部 danger `Callout` 提示失败并保留首屏兜底数据，用户仍可关闭弹窗。
  - 验证：用浏览器网络限速观察加载态出现；将 run_id 替换为不存在的值（或断开后端）打开详情时，弹窗顶部出现失败提示且弹窗可正常关闭，页面其他区域不受影响。

## 3. 扩展（P2）

- [x] 3.1 [P2] 「资源与指标」区块：以 `GET /metrics?task_key=<task_key>` 拉取后在客户端筛选 `run_id` 命中的记录，命中时展示 CPU、内存、延迟、耗时与数据行数，未命中则不渲染该区块。
  - 验证：对存在指标数据的运行打开详情可见指标区块及数值；对无指标数据的运行打开详情时该区块不出现且无报错。
- [x] 3.2 [P2] Monitor 页运行表格复用 `RunDetailModal`（同一交互与降级行为），确认不影响该页既有日志展示区域。
  - 验证：在监控页点击任一行可打开同一详情弹窗，页面原有「最近运行日志」区域展示不受影响。
