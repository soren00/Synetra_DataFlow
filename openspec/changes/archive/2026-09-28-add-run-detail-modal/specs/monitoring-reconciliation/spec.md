# Monitoring Reconciliation（运行历史详情 delta）

## Purpose

本 delta 扩展既有「运行历史」能力：在总览页的运行历史列表中，用户可点击任意一条运行记录打开详情弹窗，查看该次运行的完整上下文（运行基本信息、失败原因、任务配置上下文与运行日志），用于快速定位失败与确认执行结果。本次不新增后端端点，全部基于既有的运行、日志与任务接口。

## MODIFIED Requirements

### Requirement: 运行历史
系统 SHALL 展示任务运行历史记录，包含每次运行的运行实例标识、任务标识、触发方式（定时/外部 API/手动）、状态、行数与时间，并 SHALL 支持点击单条运行记录打开该次运行的详情。

#### Scenario: 查看运行历史
- **WHEN** 用户查看某任务
- **THEN** 系统展示该任务的历史运行记录及触发方式

#### Scenario: 打开运行详情
- **WHEN** 用户点击运行历史中的某条运行记录
- **THEN** 系统打开该次运行的详情弹窗，并展示运行实例标识、任务标识、所属项目、状态、触发方式、开始时间、结束时间、耗时、尝试次数与写入行数

#### Scenario: 查看失败原因
- **WHEN** 用户打开一条状态为失败的运行记录详情
- **THEN** 系统在详情中显著展示该次运行的失败原因文本

#### Scenario: 打开运行中的记录
- **WHEN** 用户打开一条状态为运行中的记录详情
- **THEN** 系统展示该次运行已发生的信息，结束时间与耗时以进行中占位呈现，并持续刷新运行状态与日志直至该次运行结束

#### Scenario: 关闭运行详情
- **WHEN** 用户关闭运行详情弹窗
- **THEN** 系统停止该次运行的状态与日志刷新，且不影响运行历史列表当前的筛选结果

## ADDED Requirements

### Requirement: 运行详情中的任务上下文
系统 SHALL 在运行详情中展示该次运行所属任务的配置上下文，至少包含源连接、目标连接、源对象、目标对象与写入模式；当任务配置不可获取时，系统 SHALL 以明确的不可用提示降级，且不影响运行基本信息与运行日志的展示。

#### Scenario: 展示任务上下文
- **WHEN** 用户打开某次运行的详情且该运行对应的任务配置可获取
- **THEN** 系统在该详情中展示任务的源连接、目标连接、源对象、目标对象、写入模式与调度信息

#### Scenario: 任务配置不可获取时降级
- **WHEN** 详情所关联的任务已被删除，或任务配置接口返回错误
- **THEN** 系统在任务上下文区域展示不可用提示，运行基本信息与运行日志仍正常展示

### Requirement: 运行详情中的运行日志
系统 SHALL 在运行详情中展示该次运行的日志条目，包含时间戳、级别与内容；当该次运行没有日志时，系统 SHALL 在日志区域展示明确的空状态。

#### Scenario: 查看运行日志
- **WHEN** 用户打开某次运行的详情
- **THEN** 系统按时间顺序展示该次运行的日志条目及其时间戳与级别

#### Scenario: 无日志可展示
- **WHEN** 用户打开某次运行的详情且该次运行没有任何日志记录
- **THEN** 系统在日志区域展示暂无日志的空状态，且详情其他区域正常展示

#### Scenario: 日志获取失败
- **WHEN** 某次运行的日志接口请求失败
- **THEN** 系统在日志区域展示加载失败提示与可重试入口，运行基本信息与任务上下文仍正常展示
