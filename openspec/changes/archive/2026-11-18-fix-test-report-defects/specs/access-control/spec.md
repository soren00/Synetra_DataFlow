# Spec Delta

## ADDED Requirements

### Requirement: 会话票据认证
系统 SHALL 以服务端签发的签名会话票据作为唯一身份来源：用户以用户名与口令换取票据，后续请求携带该票据；系统 SHALL 校验票据签名、有效期与账号当前状态，SHALL NOT 依据客户端自称的身份标识（如用户名请求头）授予任何权限。

#### Scenario: 登录换取票据
- **WHEN** 用户以正确的用户名与口令登录
- **THEN** 系统返回身份信息（用户名与角色）及本次签发的签名票据

#### Scenario: 携带票据访问
- **WHEN** 客户端在请求中携带有效票据
- **THEN** 系统按票据对应的账号解析身份与角色，并放行其权限范围内的操作

#### Scenario: 票据被伪造或篡改
- **WHEN** 客户端携带签名不匹配、已过期或格式非法的票据
- **THEN** 系统拒绝该请求并返回 401，不授予任何角色权限

#### Scenario: 客户端自称身份不被采信
- **WHEN** 匿名客户端仅在请求头中声明自己为某管理员用户名
- **THEN** 系统不采信该声明，按未认证处理并返回 401

#### Scenario: 账号状态变更即时生效
- **WHEN** 某账号在票据有效期内被停用、删除或其角色被调整
- **THEN** 该账号的后续请求按最新账号状态裁决：停用或删除返回 401，角色以当前角色为准

#### Scenario: 改密使旧票据失效
- **WHEN** 用户修改自己的口令，或管理员重置该用户口令
- **THEN** 该用户此前签发的票据立即失效，再次使用返回 401

#### Scenario: 登出
- **WHEN** 用户执行退出登录
- **THEN** 客户端丢弃票据并回到登录页，后续请求以未认证处理

### Requirement: 接口鉴权兜底与错误语义
系统 SHALL 对所有业务接口默认执行身份校验，仅在明确声明的公开接口（健康探针与登录）上豁免；新增接口 SHALL NOT 以匿名可访问作为默认。

#### Scenario: 匿名访问业务接口
- **WHEN** 未携带有效票据的客户端访问任一业务接口（读或写）
- **THEN** 系统返回 401，且响应中不包含业务数据

#### Scenario: 角色不足
- **WHEN** 已认证用户访问超出其角色的操作（只读用户写配置、非管理员管理用户与凭据）
- **THEN** 系统返回 403，并说明所需角色

#### Scenario: 公开接口
- **WHEN** 客户端访问健康探针或登录接口
- **THEN** 无需票据即可访问

#### Scenario: 服务凭据通道独立
- **WHEN** 外部系统以服务凭据（而非用户票据）调用任务触发接口
- **THEN** 系统按服务凭据自身的有效性与项目范围裁决并正常受理，不要求提供用户会话票据；凭据无效或已吊销时返回 401

### Requirement: 审计日志查询
系统 SHALL 提供仅管理员可见的审计日志查询能力，支持按项目与操作类型过滤、按条数限制，返回操作者、时间、项目、操作与明细；响应 SHALL NOT 包含任何明文凭证。

#### Scenario: 管理员查询审计日志
- **WHEN** 管理员在「审计日志」页签选择项目或操作类型后查询
- **THEN** 系统按时间倒序返回匹配条目，并展示操作者、时间、项目、操作与明细

#### Scenario: 非管理员被拒
- **WHEN** 开发者或只读用户请求审计日志查询接口
- **THEN** 系统返回 403，且不返回任何审计条目

## MODIFIED Requirements

### Requirement: 多用户与角色
系统 SHALL 支持多用户及角色，角色包括管理员、开发者、只读。

#### Scenario: 角色授权
- **WHEN** 管理员为用户分配角色
- **THEN** 系统按角色控制用户可执行的操作

#### Scenario: 角色操作边界
- **WHEN** 只读用户尝试发布任务、修改配置或回滚版本
- **THEN** 系统拒绝操作；只读用户仅可浏览任务、配置与运行信息

#### Scenario: 管理员自助停用
- **WHEN** 管理员尝试停用或删除自己正在使用的账号
- **THEN** 系统返回 403 并说明不能停用/删除自己的账号，该判定优先于「至少保留一名启用管理员」的 409 判定

### Requirement: 外部触发 API 凭据
系统 SHALL 支持为外部系统签发 API 凭据（服务账号），凭据绑定单一项目范围、仅具备任务触发权限，并可由管理员随时吊销。

#### Scenario: 凭据签发与使用
- **WHEN** 管理员为某项目签发 API 凭据
- **THEN** 该凭据仅可触发该项目内任务，凭据明文仅在签发时展示一次，后续仅存引用与摘要

#### Scenario: 吊销凭据
- **WHEN** 管理员吊销某 API 凭据
- **THEN** 使用该凭据的后续触发请求立即被拒绝

#### Scenario: 凭据管理界面
- **WHEN** 管理员或开发者在「权限凭据」页的「API 凭据」页签操作
- **THEN** 可按项目查看凭据列表、签发新凭据（明文仅展示一次并提示保存）并吊销既有凭据，吊销后列表状态即时更新
