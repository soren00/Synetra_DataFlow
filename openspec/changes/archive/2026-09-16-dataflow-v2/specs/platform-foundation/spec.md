## Purpose

定义 Synetra_DataFlow 的产品定位、目标用户与核心价值，并确立部署形态与 Web 视觉风格等全局约束，作为各能力域的共同前提。

## ADDED Requirements

### Requirement: 面向数据工程师的用户定位
系统 SHALL 面向懂 ETL/数仓的数据工程师设计，提供可编程、可治理的 ETL 任务开发与管理能力，而非面向无代码/低代码用户。

#### Scenario: 用户画像界定
- **WHEN** 平台面向使用人员交付
- **THEN** 使用人员需具备 ETL/数仓与 Python 开发能力，平台以灵活可编程与统一治理为核心

### Requirement: 核心价值
系统 SHALL 以灵活可编程、可选择数据生成任务（选择数据提供方与字段即可生成同步任务）、统一调度治理、一键部署省事为核心价值。

#### Scenario: 核心价值落地
- **WHEN** 数据工程师使用平台
- **THEN** 平台支持灵活编写或生成 ETL 脚本、通过选择数据提供方与字段快速生成同步任务、统一调度与治理、以及一键完成部署

### Requirement: Linux 一键部署
系统 SHALL 支持在 Linux 环境通过一键方式完成部署，包含 Web 服务、调度引擎与依赖组件；部署过程需幂等，可在同一主机重复执行而不破坏既有部署与数据。

#### Scenario: 一键部署
- **WHEN** 管理员在 Linux 主机执行部署命令
- **THEN** 系统自动完成 Web 后端、前端、调度引擎与元数据库的安装配置，各服务健康检查通过且可访问

#### Scenario: 部署幂等可重跑
- **WHEN** 部署在已部署过的主机上再次执行，或上次部署中途失败后重新执行
- **THEN** 系统跳过或修复已满足的步骤，完成后部署状态与首次成功部署一致，既有数据不丢失

### Requirement: macOS 视觉风格
系统 Web 界面 SHALL 遵循 macOS 设计语言，包括圆角、毛玻璃、层次化、8pt 网格与深浅色主题，在设计与实现阶段落地。

#### Scenario: 界面风格一致
- **WHEN** 用户打开 Web 界面
- **THEN** 界面呈现统一的 macOS 风格视觉与交互，而非默认组件外观
