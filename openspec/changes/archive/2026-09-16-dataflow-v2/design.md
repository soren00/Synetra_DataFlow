## Context

本 change 为 Synetra_DataFlow 的需求整体重写（见 proposal.md 的 Why）。当前代码侧仅有 `etl_sdk` 骨架（MOD-001，MySQL→MySQL 抽取/转换/加载），其余模块（MOD-002~013）均待开发；`openspec/specs/` 此前为空，本 change 即为全新基线。

约束：面向懂 ETL/数仓的数据工程师；调度沿用 DolphinScheduler；Web 为 FastAPI + React；元数据/日志库为 MySQL；部署为 Linux 单机一键部署。

## Goals / Non-Goals

**Goals:**
- 落地"两条独立路径"：LLM+Python 与手写 Python，二者共享调度/版本/监控，但执行通道在安全上区分对待。
- 以"档位1"安全模型约束手写 Python，不依赖 LLM。
- 通过 REST API 对外触发同步，并支持 API 作为数据源与数据目标。
- 抽象 LLM 接入层，解除对单一供应商的锁定。
- 新增主数据管理（客户/产品/组织核心实体，含质量校验与变更历史）。

**Non-Goals:**
- 不引入运行时沙箱（容器/bwrap）与静态代码扫描（本 change 定档位1，作为后续升级路径保留）。
- MDM 不做匹配合并/golden record 与去重规则。
- 不实现实时 CDC 与任务间 DAG 编排（沿用旧非目标）。
- 不自行实现任务执行器，执行仍委托 DolphinScheduler。

## Decisions

### 决策1：两条独立转换路径，执行通道分离
- 路径A（LLM+Python）：向导/对话 → 生成 SyncConfig → LLM 生成脚本 → dry-run + 静态校验 → 人工确认 → 写入 `current/`。平台生成代码视为"可信"。
- 路径B（手写 Python）：用户直接编写脚本保存，作为任务执行体，走"不受信"低权限通道执行；保存前提供可选 dry-run/语法校验，但不做内容级白名单限制。
- 规则引擎的 AST 白名单**保留**，但仅校验向导/LLM 模式下可视化规则中的"受限表达式"；手写 Python 全文不受 AST 白名单约束（DEC-005"唯一安全边界"定位废止）。
- 理由：手写提供灵活性，不受信隔离提供安全；两路径共享版本化、调度与监控。
- 备选：统一视为不受信（引入不必要的信任/性能开销）；统一视为可信（安全不可接受，否决）。

### 决策2：手写路径安全模型（档位1）落地方式
- 低权限执行身份：为手写任务配置独立 DolphinScheduler worker group 与独立低权限运行用户。
- 最小凭证：进程环境仅注入本任务声明的 `conn_key`；平台级秘密（DS token、元数据库管理凭证、其他租户凭证）不注入。
- 网络白名单：解析任务声明的源/目标端点，以 egress 白名单（iptables/nftables 或 worker 网络策略）限制出网。
- 资源配额：cgroup / worker 资源参数限制 CPU、内存、磁盘与执行超时。
- 备选：档位2（追加 Bandit/AST 静态扫描）、档位3（容器/bwrap 沙箱），作为后续升级路径。

### 决策3：REST API 触发复用 DolphinScheduler 执行链路（异步语义）
- FastAPI 新增 API 模块，接收外部触发请求 → API 凭据鉴权 → 调用 DolphinScheduler API 触发工作流 → **立即返回触发回执**（触发ID、任务ID、项目、触发时间），不同步等待执行完成；执行结果经监控/运行历史查询，首期不提供执行完成回调。
- 外部系统使用绑定项目范围、可吊销的 API 凭据（服务账号）；凭据仅限触发授权项目内任务，越权与任务不存在均返回明确错误并审计。
- 理由：复用 DS 既有执行/调度能力，不自建执行器；异步回执契合 DS 触发模型，避免长连接与超时歧义。

### 决策4：LLM 抽象接入层（脱敏 + RAG 为固定环节）
- 定义统一 Provider 接口（对话/补全、模型列表、可选流式），支持多供应商可插拔；默认实现 DeepSeek，后续可扩展；切换供应商不改变任务配置与已生成脚本。
- **脱敏**：配置在调用 LLM 前以占位符替换连接串等敏感信息，生成后由后端还原；明文凭证不出平台（沿用旧基线 RSK-003 控制）。
- **RAG 保留**：检索并注入 etl_sdk 契约文档（`docs/sdk_api.md`）与示例作为生成上下文，与具体供应商解耦，是抑制幻觉的主要手段。

### 决策5：API 作为数据源/目标通过 connector 扩展
- 在 `etl_sdk` 的 extractor/loader 抽象下新增 REST/API extractor（拉取）与 API loader（推送）。
- API 推送语义：目标端点 + 认证 + 超时/重试；幂等由目标端点约定，平台不保证幂等。

### 决策6：Linux 一键部署
- 提供部署脚本/编排，一键完成 FastAPI、React 静态资源、DolphinScheduler、MySQL 元数据库的安装与配置；推荐 systemd 服务 + 单机 MySQL，可选 docker-compose。
- 备选：K8s 编排——与"单机一键部署"约束冲突，不采用。

### 决策7：macOS 前端设计系统
- 定义 design tokens（颜色/字体/圆角/阴影/间距/8pt 网格）+ 组件映射，实现为 React 主题（CSS variables）；借鉴 HIG 设计语言，不复刻苹果版权资产。

### 决策8：MDM 落地
- 客户/产品/组织建模为可配置实体 + 字段 + 约束（非空/格式/唯一）；提供维护 API 与变更历史表；分发复用 ETL 同步链路。

### 决策9：复用 etl_sdk 契约
- 以 `etl_sdk` 的 `SyncConfig`/schema 为契约冻结点，扩展 API 源/目标与手写路径；增量+水位、upsert、dry-run、指标回写继续沿用。

### 决策10：Web 数据库/接口只读查询定位
- 对已配置连接提供两类临时取数：关系库只读 SELECT 查询、REST/API 请求调试（地址/方法/头/参数取自连接配置并可临时覆盖）；结果分页预览（默认上限 1000 行、超时 30s，常量在实现时按单机容量复核）。
- 查询结果可一键送入字段选择向导作为选源/选字段输入；首期结果不持久化、不提供导出、不做多语句/写操作（非 SELECT 与 DDL/DML 在后端语句类型检查阶段拒绝）。
- 全部查询操作走项目权限并写审计日志。
- 理由：查询功能的价值是"配任务前看数据"，不是再做一个通用 SQL 工作台；限制写操作与导出可控制数据外泄面。
- 备选：完整查询控制台（保存查询/导出/多语句）——超出本基线目标，否决。

### 决策11：血缘按路径分级
- 向导/LLM 路径：任务配置阶段依据字段映射静态推导字段级血缘（源表.字段 → 目标表.字段）。
- 手写路径：平台不解析用户代码，仅依据任务声明的源/目标连接维护表级血缘；字段级血缘标记为"不支持/未知"并在 UI 显式区分，不伪造。
- 理由：手写代码的字段级推导不可靠（RSK-005 的同类问题在手写路径无解），如实表达覆盖边界优于产出错误血缘。

### 决策12：权限与凭据体系先于对外触发落地
- 实施顺序上将多用户/角色/项目隔离/审计与外部 API 凭据管理排在 REST API 触发之前；触发接口的鉴权直接复用项目隔离模型，不另建一套。
- 水位语义补充：任务失败时不推进增量水位，水位仅在成功加载后推进（沿用"至少不丢数据"的取舍，重复拉取由 upsert 兜底）。

### 决策13：任务分期（P1/P2）
- P1 形成端到端闭环：一键部署/骨架、关系库连接与只读查询、向导与转换规则、两条脚本路径与档位1安全、权限审计（含 API 凭据）、DS 调度与 API 触发、重试邮件、基础监控对账、元数据与分级血缘、版本回滚、MySQL 之外三类关系库的抽取/加载。
- P2 扩展覆盖面：CSV/REST 源与 API/对象存储/Hive/ClickHouse 目标、阈值告警细化、MDM 全量能力。
- 理由：先以关系库场景打通"配置→生成→执行→治理"全链路，再扩连接器与 MDM，控制单机开发期的并行复杂度。

## Risks / Trade-offs

- [档位1 无静态扫描与运行时沙箱] → 由网络白名单 + 最小凭证 + 低权限身份兜底；后续补 Bandit + bwrap。
- [手写代码拖垮单机] → cgroup 资源配额 + 执行超时 + 独立 worker group。
- [LLM 幻觉生成不合规脚本] → RAG 注入 SDK 契约 + dry-run + 静态校验 + 人工确认（手写路径不依赖 LLM）。
- [单机支撑上百任务并发 IO] → 资源配额与独立 worker 池，后续可水平扩展。
- [API 目标无幂等保证] → 重试/超时策略 + 目标端点约定，在配置与文档中显式告知，记为已知限制。
- [网络白名单粒度粗] → 首期端点级白名单，后续按需细化到主机/端口。
- [只读查询成为数据外泄通道] → 语句类型白名单（仅 SELECT）、强制行数上限与超时、禁导出、项目权限与审计。
- [手写路径血缘不完整] → 仅承诺表级血缘，UI 显式标识字段级未知，避免误导治理判断。
- [外部 API 凭据泄露] → 项目范围绑定、可随时吊销、仅触发权限、调用审计。
- [任务失败后水位推进导致漏数] → 失败不推进水位，重复数据由主键 upsert 兜底。

## Migration Plan

- 本 change 为全新基线，不迁移 baseline-001；已交付的 `etl_sdk` MySQL 抽取/转换/加载能力保留并复用。
- 实施顺序（P1 先行，编号对应 tasks.md）：一键部署/骨架 → 关系库连接管理与只读查询 → 配置向导与转换规则 → 脚本生成（两路径）与档位1安全 → **权限/审计/外部 API 凭据** → DS 调度/API 触发 → 监控/对账 → 元数据/分级血缘 → 版本回滚 → 三类关系库抽取加载；随后 P2：CSV/API 源与多类型目标扩展 → 阈值告警细化 → MDM。
- 回滚：任务配置/脚本版本回滚 + 部署脚本幂等可重跑。
- 旧基线文档（`doc/项目情况与需求概览.md` 及 AI-governance-framework 下 baseline-001 文档）需标注已被本 change 取代，避免实施期引用冲突。
