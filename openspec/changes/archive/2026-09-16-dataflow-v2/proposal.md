## Why

Synetra_DataFlow 原需求基线（baseline-001）面向"无门槛的开发/运维人员"，核心价值是"降低 ETL 开发门槛"，因此设定了禁止手写 Python、固定 DeepSeek、仅单机部署、仅定时同步等约束。产品方向现已调整为面向"懂 ETL/数仓的数据工程师"，核心价值转为灵活可编程、可选择数据生成任务、统一调度治理、一键部署省事。原需求与新产品方向冲突，需整体重写需求基线（采用"推到重来 + 不捕获旧基线"的起点）。

## What Changes

- 用户画像：从"无门槛开发/运维人员"调整为"懂 ETL/数仓的数据工程师"。
- 核心价值：从"降低 ETL 开发门槛"调整为"灵活可编程、可选择数据生成任务（选择数据提供方与字段即可生成同步任务）、统一调度治理、一键部署省事"。
- 同步模式：从"仅定时同步"扩展为"定时运行 + 平台对外暴露 REST API，供外部调用触发数据同步"。
- 转换能力：**BREAKING** 从"向导 + LLM，禁止用户手写 Python"改为"两条独立路径：LLM+Python 模式 与 手写 Python 模式"；手写路径自主、不依赖 LLM。
- 转换规则安全边界的重新定位：原 AST 白名单**保留**，但仅作用于向导/LLM 模式规则引擎中的"受限表达式"；手写 Python 路径不受 AST 白名单约束，改由手写路径安全模型管控。原 DEC-005"AST 白名单唯一安全边界"的定位废止。
- 手写 Python 安全模型：档位1——低权限执行身份 + 最小凭证注入 + 网络白名单 + 资源配额（暂不做静态扫描与运行时沙箱）；四项为独立可验收控制。
- LLM：**BREAKING** 从"固定外部 DeepSeek API"改为"不限（需抽象 LLM 接入层，多供应商可插拔）"；保留 RAG（注入 etl_sdk 契约文档与示例）与"配置脱敏后调用 LLM、明文凭证不出平台"的安全要求。
- 数据源：新增 API 作为数据源（MySQL/Oracle/SQLServer/PostgreSQL + CSV + REST/API）。
- 数据目标：新增 API 作为目标（关系库/对象存储/Hive/ClickHouse + API，推数据到 API；平台不保证推送幂等，由目标端点约定）。
- 部署形态：**BREAKING** 从"单机 Linux"改为"Linux 一键部署"（部署脚本需幂等可重跑）。
- 新增主数据管理（MDM）：客户/产品/组织等核心实体，含模型定义、主数据表维护、同步分发、数据质量校验（非空/格式/唯一）、变更历史；不做匹配合并/golden record。
- Web 界面新增：数据库/接口**只读查询**功能（对已配置连接发起只读 SQL 查询或 API 请求调试，分页预览样例数据，结果可送入字段选择向导；非通用 SQL 工作台，不支持写操作、首期不提供结果导出）；字段选择同步功能（LLM+Python 模式下：查询数据提供方 → 选字段 → 选字段处理方式 → 选数据插入方 → 预览）。
- 血缘按路径区分：向导/LLM 路径基于字段映射静态推导字段级血缘；手写 Python 路径仅维护表级血缘（源/目标来自任务声明），字段级血缘不保证并在界面显式标识。
- 对外触发鉴权：外部系统通过绑定项目范围、可吊销的 API 凭据（服务账号）调用触发 API；触发为异步语义，返回触发回执，执行结果经监控能力查询。
- 前端视觉：采用 macOS 设计语言（在设计与实现阶段落地，需求阶段仅记录为一条约束）。
- 保留旧能力：增量机制（增量字段 + 水位，失败不推进水位）、主键 upsert、数据对账、血缘（按上述路径区分）、权限多租户、审计日志、监控告警、元数据字典、RAG 上下文注入、版本管理回滚、失败重试与邮件告警，全部保留。
- **BREAKING** 移除：原 DEC-005"不支持用户手写 Python / AST 白名单唯一安全边界"，被"两条独立路径 + 手写路径安全模型 + 受限表达式 AST 白名单（仅限规则引擎）"取代。

## Capabilities

### New Capabilities

- `platform-foundation`: 产品定位、用户画像、核心价值、全局约束与 Linux 一键部署（幂等可重跑）要求。
- `data-connections`: 数据源/目标连接管理（MySQL/Oracle/SQLServer/PostgreSQL/CSV/REST/API 源；关系库/对象存储/Hive/ClickHouse/API 目标）、Web 只读查询/接口调试、API 目标推送语义。
- `etl-authoring`: ETL 字段选择向导与转换规则（受限表达式保留 AST 白名单）、脚本生成（LLM+Python 与手写 Python 两条独立路径）、LLM 接入层抽象/脱敏/RAG、手写路径四项独立安全控制。
- `scheduling-execution`: DolphinScheduler 调度、定时执行、REST API 异步触发同步（API 凭据鉴权、触发回执）、版本管理与回滚。
- `monitoring-reconciliation`: 任务监控、运行历史、资源指标、监控告警、数据对账。
- `metadata-lineage`: 元数据同步（含 API 源样例推断）、字段字典、数据血缘（向导/LLM 字段级，手写路径表级）。
- `access-control`: 多用户、角色（管理员/开发者/只读）、项目/命名空间隔离、外部触发 API 凭据（服务账号）、操作审计日志。
- `master-data`: 主数据管理（客户/产品/组织核心实体：模型定义、维护、分发、质量校验、变更历史）。

## Impact

- `etl_sdk`（原 MOD-001）：转换与安全边界变化——新增手写 Python 路径与安全执行上下文；规则引擎的 AST 白名单保留并继续约束"受限表达式"；新增 REST/API extractor/loader。
- Web 后端（FastAPI）：新增 REST API 异步触发与服务账号鉴权、数据库/接口只读查询、主数据管理、两条转换路径、LLM 接入层（多供应商/脱敏/RAG）。
- Web 前端（React）：新增只读查询与请求调试、字段选择同步、血缘分级展示；落地 macOS 风格设计系统。
- DolphinScheduler 集成：定时调度 + REST API 触发 + 手写任务独立 worker group 低权限执行通道。
- 部署：新增 Linux 一键部署脚本/编排（幂等可重跑）。
- LLM 接入：供应商不再固定，需抽象统一接入层；脱敏与 RAG 为接入层的固定环节。
