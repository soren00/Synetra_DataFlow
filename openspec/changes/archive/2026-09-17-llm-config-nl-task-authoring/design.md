# Design: LLM 配置管理与自然语言对话式建任务

目标：把休眠的 LLM 接入层激活为可配置、可安全使用、可自然语言建任务的能力，复用既有校验/血缘/脚本链路，不破坏 `TaskConfig` 契约。

## 决策 1：API Key 存 Vault，env 仅作默认值

**决策**：LLM 配置（供应商、base_url、model、api_key）落元数据存储；api_key 经既有 `SecretVault.encrypt()` 加密后存储，查询接口仅返回掩码（尾 4 位）。`Settings.deepseek_*` 环境变量作为默认值：界面未配置时回退 env，均缺失时接口返回 503 引导文案。

**理由**：硬约束要求外部 API 凭据「一次性可见、可吊销」；vault.py 已提供 Fernet 对称加密，无需新依赖。env 作默认值保证一键部署场景（运维写 env）与界面场景（管理员写界面）都能用，且互不破坏。

**被否决的方案**：仅支持 env 配置、不做界面。否决理由：与「管理员可切换供应商」的既有需求矛盾，且密钥轮换需重启服务。

## 决策 2：两轮 RAG + 单轮修订

**决策**：草稿生成分两轮：第一轮注入「用户描述 + 连接清单（name/conn_key/ctype/project）」，LLM 输出骨架 JSON（source_conn_key/source_object/target_conn_key/target_object/mode 等）；第二轮注入「描述 + 骨架 + 源表结构」，输出完整 `TaskConfig` JSON。修订指令（如「改成全量」）携带当前草稿 JSON **单轮**生成修订稿，不重跑两轮。

**理由**：连接清单轻量（即使连接很多也只几百 token），第一轮收敛源/目标后第二轮才能精准注入目标表结构，避免一次塞全部 schema 超上下文；修订单轮保留既有字段映射，避免对话式调整导致映射抖动。

**被否决的方案**：单轮一次性生成（不注入结构）。否决理由：字段映射靠猜，错配率高；一次注入全部连接 schema 在连接多时超限。

## 决策 3：表结构三级降级链

**决策**：第二轮表结构来源按「① 元数据 Catalog（`GET /api/metadata/connections/{ck}/tables/{table}`）→ ② 连接只读查询 information_schema（走既有 `run_select`，天然过只读守卫）→ ③ LLM 按描述推断并标记「字段为推断，待核对」」取首个可用来源。

**理由**：Catalog 可能未同步该表；信息模式只读查询成本低且复用成熟管线；③ 保证连接不可达时流程仍可完成，配合人工确认兜底。

**被否决的方案**：仅用 Catalog，缺失就让 LLM 盲猜。否决理由：首次使用（未 sync）体验差，字段质量不可控。

## 决策 4：草稿→人工确认→复用既有保存链路

**决策**：草稿接口只返回可编辑的 JSON（含字段映射、样例预览、目标列警告），**不落库**；用户确认后前端调既有 `POST /api/tasks` 保存，表达式白名单校验、血缘推导、自动脚本生成全部复用。

**理由**：与 spec「人工确认后才生效」一致；避免草稿态污染任务表；校验链路单一来源，无双份实现。

**被否决的方案**：草稿接口直接落库再等确认。否决理由：引入草稿/确认状态机，污染任务模型与列表，收益为零。

## 决策 5：字段映射错配加固（结构校验 + 样例预览）

**决策**：草稿卡展示字段映射表；目标表已知列内不存在目标字段时打黄色警告；源连接可读时内嵌 10 行源表样例数据。预览失败不阻断草稿展示（降级为提示）。

**理由**：schema 注入解决「列存在」，语义错配（amount↔total）只能靠人眼与目标列警告双保险；样例预览复用既有 query preview，成本近零。

**被否决的方案**：仅靠映射表展示。否决理由：人读列名映射易漏错，样例数据一眼可辨。

## 决策 6：提示词注入结构性化解，不做过度防御

**决策**：system prompt 仅约束「严格输出合法 JSON 且不得虚构连接」，不引入复杂注入检测。安全性依赖三重结构：输出必须反序列化为 `TaskConfig`（任意注入文本塞不进结构）、conn_key 必须存在于连接库、草稿不落库且保存走白名单校验。

**理由**：结构性约束已收死攻击面，检测型防御是过度工程；可信度与成本最优。

**被否决的方案**：在提示词层做输入过滤/清洗。否决理由：不可靠且增加复杂度，结构校验已兜底。

## 决策 7：LLM 调用审计与默认模型

**决策**：每次生成/修订调用（含失败与自动重试）写 `store.log_event`（actor、provider、model、轮次 first/second/revise、结果）。生成路径默认使用 `deepseek-chat`，不使用 reasoner。

**理由**：外部 API 为真实花费且凭据可吊销，审计是安全闭环与后续配额决策的依据；低成本模型满足配置生成任务。

**被否决的方案**：不记录审计。否决理由：与凭据吊销的安全姿态矛盾，无法回答「谁在什么时候调了 LLM」。

## Open Questions（不影响 P1 规格与任务分解）

- 样例预览对源连接可达性的依赖：实现时按「预览失败不阻断」处理，已入 spec，不阻塞。
- 对话页入口形态（独立导航项 vs 任务页跳转）：实现时按独立导航项推进。
