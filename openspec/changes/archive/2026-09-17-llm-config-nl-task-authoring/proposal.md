# Proposal: LLM 配置管理与自然语言对话式建任务

## Why

系统已具备 LLM 接入层的抽象骨架（供应商无关注册表、DeepSeek 实现、脱敏/RAG/生成编排），但存在三个断层，导致 LLM 能力整体不可用、且缺少最契合数据工程师的建任务入口：

1. **LLM 层休眠**：`auto_register()` 从未在启动时被调用，注册表恒为空，`POST /api/scripts/generate` 必然返回 503「LLM provider 未就绪」；配置仅能通过环境变量 `SYNETRA_DEEPSEEK_*` 提供，无运行时可改的界面。
2. **无模型/API Key 配置界面**：spec 已承诺「管理员可切换 LLM 供应商」，但缺少配置入口与凭据安全存储（一次性可见、可吊销）的落地。
3. **无自然语言建任务能力**：任务创建只能手工逐字段填写向导，缺少「用一句话描述抽取需求、LLM 生成任务配置草稿、人工确认后落库」的对话式路径，与既有「LLM+Python 生成脚本」路径不连贯。

## What Changes

- **LLM 配置管理（管理员专属）**：
  - 新增配置页：供应商、Base URL、模型（由 `list_models()` 动态拉取）、API Key；API Key 明文仅保存时显示一次，落库为 Vault 密文，可吊销，可测试连通。
  - 后端新增 `GET/PUT /api/llm/config` 与 `POST /api/llm/config/test`、`DELETE /api/llm/config/key`；配置保存后热更新注册表，切换供应商不影响既有任务配置与已生成脚本。
  - 启动时调用 `auto_register()` 使环境变量配置生效；未配置 API Key 时优雅降级（调用方得到 503 与引导文案，而非崩溃）。
- **自然语言对话式建任务（独立页面）**：
  - 新增「对话式建任务」页：用户以自然语言描述抽取需求，系统经**两轮 RAG**（第一轮结合连接清单识别源/目标骨架，第二轮注入源表结构）生成 TaskConfig 草稿。
  - 表结构来源采用**三级降级链**：元数据 Catalog → 连接只读查询 information_schema → 均不可得时由 LLM 推断并标记「待核对」。
  - 草稿经 Pydantic 契约反序列化与 conn_key 存在性校验；非法输出自动带错误信息重试一次；草稿卡内展示字段映射、源表样例预览与目标列不存在警告。
  - 对话修订轮基于旧草稿**单轮生成**（不重跑两轮）；用户确认后复用现有 `POST /api/tasks` 保存链路（表达式白名单校验、血缘推导、自动脚本生成均复用）。
- **LLM 调用审计**：每次生成/修订调用落 `log_event`（用户、供应商、模型、轮次、成败），支撑凭据可吊销的安全闭环与成本可观测。

## Non-Goals（明确不做）

- 不做自然语言→SQL 查数（NL 取数只到「任务配置草稿」为止，不延伸到查询预览执行）。
- 不新增 LLM 供应商实现（仅 DeepSeek；注册表抽象保留供后续插拔）。
- 不做 LLM 用量配额/费用看板（审计日志先落地，配额后置）。
- 不改变既有任务配置/脚本的数据结构；`TaskConfig` 契约保持不变。

## Assumptions

- 环境变量作为配置默认值，界面保存的配置优先覆盖；两者都缺失时降级为 503 提示引导。
- 草稿是纯 JSON、与供应商无关；切换供应商后旧草稿不失效。
- 第 2 轮依赖的连接信息模式查询仅限只读（过既有只读守卫），连接不可达时走第 3 级降级。

## Risks

- LLM 输出质量不稳定（漏字段、语义错配、非法 JSON）：以结构校验 + 目标列警告 + 样例预览 + 人工确认四重兜底；非法 JSON 自动重试一次。
- 外部 API 真实花费：默认使用低成本模型，记录审计日志，供后续限额决策。
- 两轮调用的端到端延迟：骨架轮与表结构轮串行；修订轮单轮缓解常态延迟。
- 凭据安全：API Key 明文仅出现一次（保存请求），其余全部为 Vault 密文引用，吊销后立即生效。

## Open Questions

- 无阻塞项。样例预览对连接可达性的依赖在实现时按「预览失败不阻断草稿展示」处理（警告提示即可）。
