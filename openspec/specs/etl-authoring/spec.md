## Purpose

定义 ETL 任务的配置向导、转换规则与脚本生成能力，提供 LLM+Python 与手写 Python 两条独立路径，规定 LLM 接入层（供应商抽象、脱敏、RAG）与手写路径的四项独立安全控制，并明确增量、upsert、版本化执行语义。

## Requirements

### Requirement: 字段选择同步向导
系统 SHALL 在 LLM+Python 模式下提供字段选择同步向导，流程为查询数据提供方、选择字段、选择字段处理方式、选择数据插入方、预览；其中数据预览 SHALL 以独立的、可关闭的弹窗呈现，用户可主动打开与关闭预览，关闭后返回任务表单继续编辑。

#### Scenario: 向导配置同步任务
- **WHEN** 用户按向导依次选择数据提供方、字段、字段处理方式与数据插入方并预览
- **THEN** 系统生成对应的 ETL 任务配置，并在预览中展示字段映射与处理结果

#### Scenario: 查询结果送入向导
- **WHEN** 用户在只读查询/接口调试中选择样例结果并发起字段选择
- **THEN** 系统以该数据提供方与字段集合预填向导，用户可继续配置处理方式与数据插入方

#### Scenario: 数据预览以可关闭弹窗呈现
- **WHEN** 用户在新建任务表单中发起数据预览
- **THEN** 系统在弹窗中展示样例数据，用户可关闭弹窗回到表单，已配置内容不丢失

### Requirement: 字段映射与转换规则
系统 SHALL 支持字段映射与转换规则配置，规则类型包括字段映射、类型转换、空值填充、常量与受限表达式；受限表达式仅可使用白名单函数，禁止属性访问与内建调用。系统 SHALL 为各规则类型提供规则说明与示例、为受限表达式提供可用的函数/操作参考与示例；受限表达式的输入控件 MUST 与该规则的字段选择控件分行展示（字段在前、表达式在后），排版调整 MUST NOT 删减提示中的权威口径（受支持函数清单、源列名引用写法、切片写法、不可用的 SQL 方言写法）。

#### Scenario: 配置并预览转换规则
- **WHEN** 用户为字段配置映射、类型转换、空值填充、常量或受限表达式
- **THEN** 系统保存规则并在预览中将规则正确应用到样例数据

#### Scenario: 受限表达式白名单校验
- **WHEN** 用户保存的受限表达式引用了白名单外函数、属性访问或内建调用
- **THEN** 系统通过 AST 校验拒绝该表达式并提示原因，任务配置不被保存

#### Scenario: 白名单不约束手写路径
- **WHEN** 用户通过手写 Python 路径编写脚本
- **THEN** 系统不对脚本内容做受限表达式 AST 白名单限制，其安全由手写路径安全模型控制

#### Scenario: 规则带说明展示
- **WHEN** 用户在字段转换中选择具体规则类型
- **THEN** 系统展示该规则的说明文字与示例，说明保存与校验语义

#### Scenario: 表达式参考辅助
- **WHEN** 用户编辑受限表达式
- **THEN** 系统展示受支持函数/操作符的参考与示例，标识字段引用写法；表达式仍按白名单规则校验

#### Scenario: 表达式输入独立成行
- **WHEN** 用户把某条字段规则的规则类型选择为受限表达式
- **THEN** 该规则的源字段、规则类型与目标字段展示在一行，表达式输入控件在其下方独立成行展示，且同一表单内多条规则互不挤压

#### Scenario: 提示口径不因排版收窄
- **WHEN** 用户查看表达式提示
- **THEN** 提示中仍完整给出受支持函数清单、源列名引用写法、切片写法与不可用的 SQL 方言写法，前端展示的函数清单与后端权威白名单保持一致

### Requirement: 字段转换规则逐行删除
系统 SHALL 允许用户删除字段转换中的任意一条规则：每条规则行内提供删除入口，删除操作仅影响被删除的那条规则，不影响其余规则；系统 SHALL 不再提供仅能删除末尾规则、无法删除中间规则的批量删除入口。

#### Scenario: 删除任意一条规则
- **WHEN** 用户在字段转换列表中点击某条规则的「删除」按钮
- **THEN** 系统仅删除该条规则，其余规则的源字段、目标字段与规则类型保持不变

#### Scenario: 删除至空展示空态
- **WHEN** 用户删除字段转换列表中的最后一条规则
- **THEN** 系统展示「未配置字段映射」的空态提示，且不残留空白规则行

### Requirement: LLM 接入层与配置管理
系统 SHALL 提供供应商无关的统一 LLM 接入层，支持多轮对话（消息列表）、单轮补全与模型列表能力；并 SHALL 提供管理员专属的 LLM 配置管理，支持配置供应商、Base URL、模型与 API Key，配置保存后热切换生效；切换供应商不改变既有任务配置、已生成脚本与会话历史语义；配置缺失或 API Key 未配置时生成请求 SHALL 优雅降级为明确的引导性错误。

#### Scenario: 切换 LLM 供应商
- **WHEN** 管理员将 LLM 供应商由一家切换为另一家
- **THEN** 既有任务配置与脚本不受影响，后续生成请求经由新供应商完成

#### Scenario: 多轮与单轮统一入口
- **WHEN** 调用方以消息列表发起多轮对话，或以单条 prompt 发起补全
- **THEN** 二者经由同一供应商抽象完成，单轮补全作为多轮调用的特例，返回文本结果

#### Scenario: 保存配置并热切换
- **WHEN** 管理员保存新的供应商/模型/API Key 配置
- **THEN** 系统更新生效配置，后续生成请求经新配置完成，既有任务配置与脚本不受影响

#### Scenario: 测试连通性
- **WHEN** 管理员发起配置测试
- **THEN** 系统调用该供应商的模型列表接口验证凭据有效，并反馈连通结果与可选模型列表

#### Scenario: 未配置时优雅降级
- **WHEN** LLM 配置缺失或 API Key 未配置且生成请求被发起
- **THEN** 系统返回明确的引导性错误（如 503 与「请先配置 LLM」提示），不产生崩溃或静默失败

### Requirement: LLM 凭据安全存储
系统 SHALL 将 API Key 加密存储于 Vault，明文仅可在保存配置时展示一次；配置查询接口不得返回明文，管理员可吊销凭据且吊销即时生效。

#### Scenario: 明文仅一次可见
- **WHEN** 管理员提交包含 API Key 的配置
- **THEN** 系统加密存储该 Key，任何后续查询仅返回脱敏标记（如掩码尾 4 位），明文不再出现

#### Scenario: 吊销凭据即时生效
- **WHEN** 管理员吊销已保存的 API Key
- **THEN** 该 Key 的密文被清除，此后发起生成请求返回未配置引导错误

### Requirement: LLM 配置脱敏
系统 SHALL 在调用 LLM 前对任务配置中的连接串、口令、密钥等敏感信息以占位符脱敏，明文敏感信息不得出现在发往 LLM 的请求中；生成结果由后端依据占位符还原。

#### Scenario: 敏感信息不出平台
- **WHEN** 系统向 LLM 发送包含连接配置的生成请求
- **THEN** 请求内容仅含占位符引用，明文凭证不离开平台，生成脚本中的占位符在保存前被还原为运行时引用

### Requirement: LLM RAG 上下文注入
系统 SHALL 在 LLM 生成前检索并注入 etl_sdk 契约文档、表达式技能包与示例作为上下文；该上下文在生成会话中作为会话级上下文存在一次、不在每轮重复注入，且 RAG 注入与具体供应商无关。

#### Scenario: 生成请求携带 SDK 契约
- **WHEN** 系统向 LLM 发起脚本生成请求
- **THEN** 请求上下文中包含当前 etl_sdk 的契约文档与示例，以约束生成代码符合 SDK 规范

#### Scenario: 生成请求携带表达式技能包
- **WHEN** 系统向 LLM 发起脚本生成请求
- **THEN** 请求上下文中同时包含表达式技能包，使生成脚本内联的受限表达式符合白名单与使用规范

### Requirement: LLM+Python 生成路径
系统 SHALL 支持通过 LLM 对话生成 Python ETL 脚本，LLM 供应商不限定；生成后需经 dry-run 与静态校验通过，并经人工预览确认后方可生效。

#### Scenario: LLM 生成脚本并确认生效
- **WHEN** 用户通过 LLM 对话描述同步需求并收到生成脚本
- **THEN** 系统执行 dry-run 与静态校验，脚本仅在通过校验且用户人工确认后写入当前版本

#### Scenario: 校验失败不生效
- **WHEN** 生成脚本未通过 dry-run 或静态校验
- **THEN** 系统拒绝生效并反馈失败原因，用户可要求重新生成

### Requirement: 手写 Python 路径
系统 SHALL 提供独立的手写 Python 路径，允许数据工程师直接编写 Python ETL 代码，不依赖 LLM；保存前提供可选的语法校验与 dry-run（dry-run 不写入目标）。

#### Scenario: 手写并保存脚本
- **WHEN** 用户在手写路径直接编写 Python 脚本并保存
- **THEN** 系统保存该脚本作为任务执行体，可被调度执行

#### Scenario: 手写脚本 dry-run
- **WHEN** 用户在保存前对手写脚本发起 dry-run
- **THEN** 系统按真实配置运行抽取与转换流程但不写入目标，并向用户返回校验结果

### Requirement: 手写路径低权限执行身份
系统 SHALL 让手写 Python 任务以非 root 的低权限用户身份、在受资源配额限制的隔离进程内运行，手写任务不得以 root 或平台服务账号运行；该隔离由平台自身提供，不依赖外部调度引擎或 worker group。

#### Scenario: 低权限运行
- **WHEN** 手写 Python 任务被执行
- **THEN** 进程以非 root 的低权限用户身份、在受资源配额限制的隔离环境中运行

### Requirement: 手写路径最小凭证注入
系统 SHALL 仅向手写任务进程注入该任务声明的 conn_key 对应凭证，不注入平台级秘密（调度令牌、元数据库管理凭证）与其他项目/租户的凭证。

#### Scenario: 进程环境最小化
- **WHEN** 手写 Python 任务启动执行
- **THEN** 其进程环境中仅包含本任务声明的凭证，无法读取平台级秘密或其他项目的连接凭证

### Requirement: 手写路径网络白名单
系统 SHALL 依据手写任务声明的源与目标端点配置出网白名单，任务仅可访问白名单内网络端点。

#### Scenario: 越权出网被拒
- **WHEN** 手写任务运行中访问未声明的主机或端口
- **THEN** 该网络访问被拒绝并记录，白名单内声明端点访问正常

### Requirement: 手写路径资源与时长配额
系统 SHALL 对手写任务限制 CPU、内存、磁盘与执行时长，超配额的任务被限流或终止并记录。

#### Scenario: 超配额终止
- **WHEN** 手写任务运行超过配置的资源或时长配额
- **THEN** 系统终止或限流该任务并记录超限事件

### Requirement: 增量同步机制
系统 SHALL 支持按用户配置的增量字段与水位进行增量抽取；水位仅在任务成功加载后推进，任务失败时保持原水位。

#### Scenario: 增量抽取并推进水位
- **WHEN** 任务配置了增量字段与水位且本次执行成功
- **THEN** 系统仅抽取水位之后新增或变更的数据，加载成功后推进水位

#### Scenario: 失败不推进水位
- **WHEN** 任务执行失败
- **THEN** 增量水位保持不变，下次调度从原水位重新抽取，重复数据由主键 upsert 兜底

### Requirement: 主键 upsert
系统 SHALL 支持按主键执行 upsert，主键存在则更新、不存在则插入。

#### Scenario: upsert 写入
- **WHEN** 同步数据到达目标且目标存在主键
- **THEN** 主键已存在的记录被更新，不存在的记录被插入

### Requirement: 物理脚本与版本化
系统 SHALL 生成物理 Python 脚本文件，并采用 current/versions 原子替换与版本记录。

#### Scenario: 生成并版本化
- **WHEN** 任务配置或脚本生成成功
- **THEN** 系统以原子方式更新 current/ 下的脚本，并写入版本记录，包括版本号、配置快照、生成人、时间、脚本路径

### Requirement: 抽取模式多字段组件
系统 SHALL 支持按所选抽取模式动态展开其所需的多个配置字段；增量模式提供增量字段、水位字段与首跑策略，upsert 模式提供主键多值编辑，而非仅一个模式单值下拉。

#### Scenario: 增量模式展开多字段
- **WHEN** 用户选择增量模式
- **THEN** 表单展开增量字段、水位字段与首跑策略等控件，供用户分别配置

#### Scenario: upsert 模式主键多值
- **WHEN** 用户选择主键 upsert 模式
- **THEN** 表单允许以多值形式维护主键字段（空则按目标全表覆盖语义处理），并可编辑覆盖语义

### Requirement: 自然语言任务草稿生成
系统 SHALL 支持用户以自然语言描述抽取需求，经两轮 RAG（第一轮结合连接清单识别源/目标骨架，第二轮注入源表结构）生成 TaskConfig 草稿；草稿须通过结构契约与连接存在性校验，并经人工确认后方可保存为任务。

#### Scenario: 两轮生成草稿
- **WHEN** 用户以自然语言描述抽取需求（含源/目标对象、模式、主键、增量水位等）
- **THEN** 系统识别骨架后注入源表结构，生成可反序列化的 TaskConfig 草稿并展示字段映射

#### Scenario: 连接校验拒绝虚构连接
- **WHEN** 草稿引用了连接库中不存在的 conn_key
- **THEN** 系统拒绝该草稿并提示连接不存在，不进入保存流程

#### Scenario: 非法输出自动重试
- **WHEN** LLM 输出无法反序列化为 TaskConfig 契约
- **THEN** 系统携带解析错误信息自动重试一次；仍失败则向用户反馈生成失败

### Requirement: 表结构三级降级链
系统 SHALL 在第二轮回合按「元数据 Catalog → 连接只读查询 information_schema → LLM 推断」的优先级获取源表结构；结构不可得时生成的草稿须标记字段为推断待核对。

#### Scenario: Catalog 命中
- **WHEN** 源表结构已存在于元数据 Catalog
- **THEN** 系统直接使用该结构注入第二轮上下文，不额外查询

#### Scenario: 实时信息模式降级
- **WHEN** Catalog 无该表结构且连接可读
- **THEN** 系统以只读方式查询该连接的信息模式获取列信息并注入第二轮上下文

#### Scenario: 推断标记
- **WHEN** Catalog 与信息模式均不可得
- **THEN** 系统由 LLM 按描述推断字段，草稿中标注「字段为推断，待核对」

### Requirement: 草稿人工确认与样例佐证
系统 SHALL 在草稿卡中展示字段映射、源表样例数据与目标列存在性警告，草稿仅在用户确认后经既有任务保存链路落库。

#### Scenario: 目标列警告
- **WHEN** 草稿中的目标字段不在目标表已知列内
- **THEN** 系统在草稿卡中对该字段标注警告，不影响用户确认

#### Scenario: 样例预览
- **WHEN** 草稿生成且源连接可读
- **THEN** 系统在草稿卡中展示源表样例数据供用户核对，预览失败不阻断草稿展示

#### Scenario: 确认后走既有保存链路
- **WHEN** 用户确认草稿
- **THEN** 系统复用任务保存链路（表达式白名单校验、血缘推导、脚本生成）落库，行为与手工向导保存一致

### Requirement: LLM 调用审计
系统 SHALL 为每次 LLM 生成/修订/修复调用记录审计事件，包含用户、供应商、模型、会话标识、轮次序号与成败结果。

#### Scenario: 生成调用留痕
- **WHEN** 任意生成、修订或修复请求完成（含失败）
- **THEN** 系统写入审计事件，可在事件日志中按任务/用户检索到该次调用

#### Scenario: 一次多轮会话可回溯
- **WHEN** 一次多轮生成会话完成后查看审计事件
- **THEN** 该会话的各轮次按会话标识与轮次序号可还原出完整调用轨迹

### Requirement: 目标表缺失自动建表
系统 SHALL 在写入目标前探测目标表，缺失时按字段映射自动创建目标表（列类型由字段规则的 cast_to/kind 映射，方言按目标连接类型适配；主键按任务主键声明）；已存在的表不得被改动。

#### Scenario: 缺失表自动创建
- **WHEN** 任务运行且目标表不存在
- **THEN** 系统按字段映射生成 DDL 自动建表后继续写入，运行成功

#### Scenario: 无列定义时明确报错
- **WHEN** 目标表不存在且无字段映射与样例数据可推断列
- **THEN** 系统返回明确错误提示先手动创建目标表

#### Scenario: 非法标识符拒绝
- **WHEN** 自动建表涉及的表名或列名包含非法标识符
- **THEN** 系统拒绝建表并提示，不拼接执行任意 SQL

### Requirement: 草稿连接由用户指定并强制生效
系统 SHALL 允许用户在草稿请求中指定源/目标连接；指定后该连接在骨架识别中声明必须使用，且草稿结果强制以用户指定连接为准。

#### Scenario: 用户指定连接覆盖
- **WHEN** 用户下拉指定源/目标连接且 LLM 骨架输出不同连接
- **THEN** 系统以用户指定连接为准生成草稿，不采用 LLM 误判的连接

### Requirement: LLM 请求层错误处理
系统 SHALL 对 LLM 请求层错误（HTTP 4xx/5xx、网络错误）不执行输出重试，直接返回失败并透出供应商返回的可读原因；仅输出内容无法解析时按契约重试一次。

#### Scenario: 供应商 400 不重试
- **WHEN** LLM 供应商返回 400（如模型名无效）
- **THEN** 系统直接返回失败并展示供应商 error.message 原因，不将其误判为输出非法而重试

### Requirement: 对话页生成反馈与创建确认
系统 SHALL 在对话式建任务页生成/修订等待期间展示转圈反馈，并在确认创建任务成功后以弹窗告知；失败时弹窗展示原因。

#### Scenario: 等待转圈
- **WHEN** 用户发起草稿生成或修订且请求处理中
- **THEN** 页面在对话流中展示加载转圈与处理文案，请求完成前输入被锁定

#### Scenario: 创建结果弹窗
- **WHEN** 用户确认创建任务
- **THEN** 系统以弹窗告知创建成功（含任务名与查看指引）或失败（含具体原因）

### Requirement: 多轮对话生成会话
系统 SHALL 在 AI 生成 ETL 任务时与 LLM 进行多轮对话：同一生成会话内的骨架识别、源表结构注入、完整草稿、对话修订与表达式修复，各轮次作为连续的对话轮次构成会话历史；后续轮次在既有历史上追加，而非仅携带当前指令、重新拼接全部上下文。

#### Scenario: 多轮次构成连续会话
- **WHEN** 用户描述需求并触发草稿生成
- **THEN** 骨架识别轮、源表结构注入轮与完整草稿轮作为同一会话的连续轮次依次发生，后续轮次在既有轮次历史上追加

#### Scenario: 修订轮基于会话历史
- **WHEN** 用户在已有草稿上提出修订指令
- **THEN** 系统在会话历史（含用户原始需求与已识别骨架）基础上追加修订轮，既不重跑骨架识别，也不以「客户端重新提交草稿 JSON」作为唯一上下文

#### Scenario: 会话级上下文不重复注入
- **WHEN** 同一会话发起第二次及之后的轮次
- **THEN** 系统提示与表达式技能包仅作为会话级上下文存在一次，不在每轮重复追加

#### Scenario: 供应商切换不破坏会话
- **WHEN** 管理员切换 LLM 供应商后在同一会话继续发起轮次
- **THEN** 会话历史与既有轮次继续可用，后续轮次由新供应商完成

### Requirement: 会话历史契约与回传校验
系统 SHALL 定义模型可见会话历史的契约（角色白名单、轮次顺序、内容来源），并在响应中返回该历史供客户端原样回传；服务端 MUST 对回传历史做契约校验与长度裁剪，且不依赖跨请求内存状态。

#### Scenario: 历史回传后继续会话
- **WHEN** 客户端携带上一次响应返回的会话历史发起下一轮
- **THEN** 服务端校验通过后在历史末尾追加本轮输入，形成连续会话

#### Scenario: 非法历史被拒绝
- **WHEN** 回传的历史包含非法角色、结构不合法或轮次顺序错乱
- **THEN** 系统拒绝该请求并返回可读原因，且不向 LLM 发起调用

#### Scenario: 历史超限裁剪
- **WHEN** 会话历史超过配置的轮次或字符上限
- **THEN** 系统裁剪最早的非会话级轮次后继续，会话级提示与表达式技能包不被裁剪

#### Scenario: 历史不含明文凭据
- **WHEN** 会话历史中包含连接信息与源表结构
- **THEN** 其中敏感信息仍以占位符形式存在，明文凭证不出平台

#### Scenario: 服务端无跨请求状态
- **WHEN** 同一用户在不同请求中继续同一会话
- **THEN** 服务端仅依据请求携带的历史与连接清单完成本轮生成，不依赖进程内会话状态

### Requirement: 表达式技能包内容契约
系统 SHALL 随服务分发一份面向 LLM 的受限表达式技能包，覆盖五类转换规则（字段映射、常量、空值填充、类型转换、受限表达式）的语义与选择判据、`fields[].expression` 的配置形态与字段引用写法、受支持函数与禁止项清单、正反例对照与常见需求配方；技能包以自然语言陈述规范，不依赖阅读源码即可正确书写表达式。

#### Scenario: 技能包覆盖五类规则
- **WHEN** 打开表达式技能包
- **THEN** 其中包含 direct/constant/null_fill/cast/expression 五类规则的语义、各自可用字段与选择判据，并说明「能用更简单的规则类型表达时不应使用受限表达式」

#### Scenario: 技能包覆盖字段引用与函数清单
- **WHEN** 阅读表达式技能包中关于表达式书写的章节
- **THEN** 其中给出「源字段列名即变量名、仅合法标识符列名可引用」的写法说明，以及每个受支持函数的签名、语义与边界行为

#### Scenario: 技能包给出反例对照与配方
- **WHEN** 阅读表达式技能包中关于常见错误与场景配方的章节
- **THEN** 其中列出常见误写（属性访问、内建调用、SQL 习惯函数、字符串格式化等）及其等价正确写法，并给出常见需求（拼接、去空格、大小写归一、四舍五入、数值/布尔转换、兜底默认值等）的表达式配方

### Requirement: 表达式技能包与白名单同源
系统 SHALL 以单一事实源维护受支持函数与禁止项，使技能包列出的函数与禁止项、表达式校验器的 AST 白名单、生成脚本运行时的可用函数集合三者一致；任一处不一致时以表达式校验器为准，且该不一致 MUST 被测试检出。

#### Scenario: 文档与校验器一致性断言
- **WHEN** 技能包列出的受支持函数集合与表达式校验器白名单不一致
- **THEN** 一致性测试失败，构建可检出该偏差

#### Scenario: 生成脚本运行时同源
- **WHEN** 生成脚本对受限表达式求值
- **THEN** 其可用函数集合与保存时校验器使用的白名单一致，不存在独立维护的第二份函数清单

#### Scenario: 技能包正反例可执行
- **WHEN** 逐一求值技能包中的正例、逐一校验技能包中的反例
- **THEN** 正例全部通过校验，反例全部被拒绝并给出违规原因

### Requirement: 表达式技能注入两条生成路径
系统 SHALL 在两条 AI 生成路径注入表达式技能包：①自然语言→TaskConfig 草稿生成与对话修订（作为会话级上下文注入）；②TaskConfig→Python 脚本生成（随 RAG 契约注入）。注入与具体 LLM 供应商无关，且不降低既有脱敏要求。

#### Scenario: 草稿生成与修订路径注入
- **WHEN** 用户发起草稿生成或对话修订
- **THEN** 发往 LLM 的请求上下文中包含表达式技能包

#### Scenario: 脚本生成路径注入
- **WHEN** 系统请求 LLM 生成同步脚本
- **THEN** 请求上下文同时包含 etl_sdk 契约与表达式技能包，使脚本内联的受限表达式同样受规范约束

#### Scenario: 供应商无关
- **WHEN** 管理员切换 LLM 供应商后再次发起生成
- **THEN** 表达式技能包仍被注入，注入内容与切换前一致

#### Scenario: 注入不削弱脱敏
- **WHEN** 表达式技能包被注入生成请求
- **THEN** 任务配置中的连接串、口令、密钥等敏感信息仍以占位符脱敏，明文凭证不出平台

### Requirement: 规则类型选择引导
系统 SHALL 在生成提示中给出五类转换规则的选择判据，并要求 LLM 优先使用更简单的规则类型，仅在无法用字段映射、常量、空值填充或类型转换表达时才使用受限表达式。

#### Scenario: 提示含规则选择判据
- **WHEN** 构建自然语言建任务的生成提示
- **THEN** 提示中给出五类规则的选择判据与字段配置示例（含受限表达式的配置形态）

#### Scenario: 简单场景不产出表达式
- **WHEN** 用户需求可由类型转换、空值填充或字段映射表达
- **THEN** 生成的字段规则使用对应规则类型，而非受限表达式

### Requirement: 生成后表达式校验回环
系统 SHALL 对 AI 生成的草稿与脚本执行表达式白名单校验，存在违规时携带「字段 + 违规原因 + 规范要点」作为同一会话的后续轮次请求 LLM 修复；修复轮次受限，达到上限后停止并返回可读结果，不得无界循环。

#### Scenario: 违规自动修复
- **WHEN** 生成的草稿包含白名单外函数调用或属性访问
- **THEN** 系统在同一会话中追加修复轮，修复后的草稿通过表达式校验并展示给用户

#### Scenario: 修复轮次受限
- **WHEN** 达到修复轮次上限后表达式仍存在违规
- **THEN** 系统停止修复并返回可读的失败或告警结果，不继续调用 LLM

#### Scenario: 合规草稿不额外调用
- **WHEN** 生成的草稿中全部表达式一次通过校验
- **THEN** 系统不发起修复轮次，草稿直接展示

#### Scenario: 脚本路径同样校验
- **WHEN** LLM 生成的脚本中内联的受限表达式违规
- **THEN** 系统在生成结果反馈中给出表达式违规原因，该脚本不得直接生效

### Requirement: 表达式违规可见且不落库
系统 SHALL 在草稿卡与任务表单按字段展示表达式校验结果，含违规字段与原因；含违规表达式的配置不得保存为任务。

#### Scenario: 字段级展示违规原因
- **WHEN** 草稿或表单中某字段的表达式未通过白名单校验
- **THEN** 系统在该字段处展示违规原因，与通过的字段可区分

#### Scenario: 违规配置不可保存
- **WHEN** 用户尝试保存含违规表达式的任务配置
- **THEN** 系统拒绝保存并提示违规字段与原因，任务配置不被落库

#### Scenario: 依据告警在会话中修订
- **WHEN** 用户针对表达式违规告警在同一会话发起修订指令
- **THEN** 系统按修订轮追加生成修订草稿，修订后的表达式通过白名单校验

### Requirement: 表达式 AI 生成
系统 SHALL 允许用户针对单条字段规则，以自然语言提示词生成受限表达式：请求 MUST 携带该字段的上下文（源字段、目标字段，以及可得的源列清单），生成的候选表达式 MUST 经表达式白名单校验后方可展示；校验未通过时 SHALL 在同一会话内发起受限次数的修复轮，达到上限仍未通过时返回可读失败原因，不得无界循环。生成结果仅作为建议回填到表达式输入，MUST NOT 自动保存任务。

#### Scenario: 按提示词生成表达式
- **WHEN** 用户在字段规则的表达式处输入提示词并发起 AI 生成
- **THEN** 系统返回一个可展示的受限表达式候选并回填到该规则的表达式输入，用户可继续手工修改

#### Scenario: 生成结果仍受白名单校验
- **WHEN** 候选表达式使用了白名单外的函数、属性访问或其他被禁写法
- **THEN** 系统发起修复轮并重新校验；修复后通过的候选被回填，仍不通过的返回可读失败原因且不修改用户已填内容

#### Scenario: 未配置模型时的优雅降级
- **WHEN** LLM 未配置或凭据不可用时用户发起表达式生成
- **THEN** 系统返回明确的引导性提示，表达式输入内容保持不变，不影响表单其他字段编辑与保存

#### Scenario: 生成不绕过保存校验
- **WHEN** 用户采用 AI 生成的表达式并保存任务
- **THEN** 表达式仍经过既有保存链路的白名单校验，违规表达式不得保存为任务

### Requirement: AI 对话页重置
系统 SHALL 在 AI 生成 ETL 任务页提供重置能力，一键把该页恢复到初始态，包括清空对话流、当前草稿、表达式校验结果、告警与样例预览、以及已选择的源/目标连接上下文。

#### Scenario: 一键重置
- **WHEN** 用户在已有对话与草稿的页面上触发重置
- **THEN** 对话流、草稿卡、校验与告警信息、样例预览与已选连接均被清空，页面回到首次进入时的状态

#### Scenario: 重置后开始新会话
- **WHEN** 用户重置后重新提交描述
- **THEN** 系统以全新会话生成草稿，不携带上一轮会话历史

### Requirement: AI 生成与创建记录
系统 SHALL 为每次在 AI 生成路径上「确认创建任务」的操作留存一条记录，无论创建成功或失败；记录 SHALL 包含本次的提示词链（用户首次描述与该草稿的历次修订指令）、创建结果状态、失败原因、所属项目、任务标识与操作者。失败记录中的草稿快照仅用于诊断复核，MUST NOT 作为任务落库、MUST NOT 可执行，且记录 MUST NOT 包含明文凭证。

#### Scenario: 创建成功留痕
- **WHEN** 用户在 AI 生成路径上确认创建任务且创建成功
- **THEN** 系统写入状态为成功的记录，含本次提示词链、任务标识、所属项目与操作者

#### Scenario: 创建失败留痕
- **WHEN** 用户确认创建任务但保存被拒绝（如表达式校验未通过或服务错误）
- **THEN** 系统写入状态为失败的记录，含本次提示词链与失败原因，且任务未被创建

#### Scenario: 记录不等同于任务落库
- **WHEN** 一条创建失败的记录包含带有违规表达式的草稿快照
- **THEN** 该草稿不进入任务库、不可被运行或执行，仅可在记录中查看；含违规表达式的配置仍然不得保存为任务

#### Scenario: 记录不含明文凭证
- **WHEN** 记录的提示词链与草稿快照中涉及连接信息
- **THEN** 连接串、口令与密钥仍以占位符形式存在，明文凭证不出平台

### Requirement: 生成记录页浏览
系统 SHALL 提供生成记录的浏览页面，支持服务端分页与按状态筛选，并从 AI 生成 ETL 任务页提供进入入口；该页面 SHALL 提供返回 AI 生成 ETL 任务页的入口。

#### Scenario: 进入与返回
- **WHEN** 用户在 AI 生成 ETL 任务页点击查看生成记录，随后点击返回
- **THEN** 系统先展示生成记录列表，返回后回到 AI 生成 ETL 任务页的对话界面

#### Scenario: 分页浏览
- **WHEN** 生成记录超过一页
- **THEN** 系统按服务端分页返回记录总数与当前页数据，用户可切换页码与每页条数

#### Scenario: 按状态筛选
- **WHEN** 用户按创建成功或创建失败筛选记录
- **THEN** 系统仅展示符合该状态的记录，并在筛选后保持分页信息正确

#### Scenario: 查看记录详情
- **WHEN** 用户展开一条生成记录
- **THEN** 系统展示该次的提示词链、创建结果与失败原因（如有）以及产生的任务标识（如有）
