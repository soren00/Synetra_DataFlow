## Purpose

定义数据源与数据目标的连接管理能力，覆盖主流关系库、CSV、REST/API 数据源，以及关系库、对象存储、Hive、ClickHouse、API 数据目标；并提供面向任务配置的 Web 只读查询/接口调试能力（含库表视图导航与点击表名预填）与 API 目标推送语义。

## Requirements

### Requirement: 支持的数据源类型
系统 SHALL 支持 MySQL、Oracle、SQL Server、PostgreSQL、CSV 文件、REST/API 作为数据源。

#### Scenario: 配置关系库数据源
- **WHEN** 用户新增数据源并选择 MySQL、Oracle、SQL Server、PostgreSQL 之一
- **THEN** 系统保存连接配置并可测试连通性

#### Scenario: 配置 API 数据源
- **WHEN** 用户新增数据源并选择 REST/API 类型
- **THEN** 系统保存请求地址、认证与参数配置并可用于后续拉取数据

### Requirement: 支持的数据目标类型
系统 SHALL 支持关系库、对象存储、Hive、ClickHouse 与 API 作为数据目标。

#### Scenario: 配置 API 数据目标
- **WHEN** 用户新增数据目标并选择 API 类型
- **THEN** 系统保存推送端点与认证配置，用于将同步结果推送到 API

### Requirement: 连接凭证安全
系统 SHALL 通过 conn_key 指向安全存储管理连接凭证，不将明文凭证内联进任务配置或写入版本库。

#### Scenario: 凭证脱敏存储
- **WHEN** 用户保存包含口令或密钥的连接配置
- **THEN** 系统仅保存 conn_key 引用，明文凭证不进入配置快照、脚本或版本记录

### Requirement: 连接测试
系统 SHALL 支持对数据源与数据目标执行连接测试，并返回成功或失败原因。

#### Scenario: 连接测试成功
- **WHEN** 用户对已配置连接执行测试
- **THEN** 系统返回连接成功或明确的失败原因

### Requirement: 关系库只读查询
系统 SHALL 支持用户在 Web 界面对已授权的关系库连接发起只读 SELECT 查询并分页预览结果，查询强制行数上限与执行超时。

#### Scenario: 只读查询返回结果
- **WHEN** 用户对已配置关系库提交 SELECT 查询
- **THEN** 系统在权限校验通过后执行查询，分页返回不超过行数上限的结果集

#### Scenario: 拒绝写操作与多语句
- **WHEN** 用户提交的语句包含非 SELECT、DDL/DML 或多条语句
- **THEN** 系统在执行前拒绝该语句并提示仅允许只读单语句查询

### Requirement: REST/API 请求调试
系统 SHALL 支持用户对已配置的 REST/API 数据源发起请求调试，查看返回样例，并可将样例字段送入字段选择向导。

#### Scenario: 调试 API 数据源
- **WHEN** 用户基于连接配置发起一次 API 请求（可临时覆盖方法、头与参数）
- **THEN** 系统返回响应样例与状态，并可从样例字段直接发起字段选择向导

### Requirement: 查询审计与边界
系统 SHALL 对所有只读查询与 API 调试操作执行项目权限校验并记录审计日志；查询结果首期不持久化、不提供导出。

#### Scenario: 查询操作留痕
- **WHEN** 用户执行关系库查询或 API 请求调试
- **THEN** 系统校验其项目访问权限并记录操作者、时间、连接与查询/请求摘要

### Requirement: API 目标推送语义
系统 SHALL 按配置的目标端点、认证、超时与重试向 API 目标推送同步结果；推送幂等性由目标端点约定，平台不保证幂等，并需在配置中显式告知。

#### Scenario: 推送到 API 目标
- **WHEN** 同步任务以 API 为目标执行加载
- **THEN** 系统按配置将结果推送到目标端点，超时或失败时按重试策略处理

#### Scenario: 幂等限制告知
- **WHEN** 用户配置 API 数据目标
- **THEN** 系统明确提示平台不保证推送幂等，需由目标端点自行保证

### Requirement: 双向连接方向
系统 SHALL 支持连接方向枚举 `source | target | both`；方向为 `both` 的连接在新建 ETL 任务时既可作为数据源亦可作为数据目标被选择。

#### Scenario: 双向连接可作源或目标
- **WHEN** 用户在连接管理中把某连接方向设为「双方（both）」
- **THEN** 该连接同时出现在「数据源」与「数据目标」的可选项中，可在同一任务中或跨任务被任一角色选用

#### Scenario: 单向连接保持原语义
- **WHEN** 用户保留连接的 source 或 target 方向
- **THEN** 该连接仅在其对应方向的任务下拉中可见，存取行为与既有版本一致

### Requirement: 只读查询展示真实数据
系统 SHALL 在只读查询页与 ETL 任务数据预览中以「行按列顺序对应取值」的方式渲染关系库查询结果，单元格显示实际数据值而非统一占位符。

#### Scenario: 关系库查询结果展示
- **WHEN** 用户对关系库连接执行 SELECT 并查看结果表格
- **THEN** 每个单元格显示该行该列的真实值（数值/字符串/空值按语义展示），不再统一显示横线占位符

#### Scenario: API 样例结果展示
- **WHEN** 用户查看 REST/API 连接的样例数据
- **THEN** 系统按对象键值渲染字段值，保持既有展示语义

### Requirement: Postman 式 REST/API 连接配置
系统 SHALL 在 REST/API 连接的配置表单中提供结构化录入：HTTP 方法以下拉选择、认证方式以下拉选择，并支持 Query Params 与 Headers 的键值对列表编辑，而非仅自由文本输入。

#### Scenario: 下拉选择方法与认证
- **WHEN** 用户配置 REST/API 连接
- **THEN** HTTP 方法在 GET/POST/PUT/DELETE 等选项中选择，认证方式在 none/bearer/basic 中选择，不依赖手输

#### Scenario: 键值对结构化录入
- **WHEN** 用户为 REST/API 连接补充请求
- **THEN** 系统允许以键值对形式维护 Query Params 与 Headers，保存后用于样例拉取与只读调试

### Requirement: 关系库库表与视图实时枚举
系统 SHALL 对已授权的关系库连接实时枚举目标库的 schema、表与视图，作为只读查询工作台的导航数据来源；枚举 SHALL 直接读取目标库的系统目录，SHALL 不依赖本地已同步的元数据字典（本地字典可能缺失或过期，不可作为导航依据）。

#### Scenario: 枚举 MySQL 连接的表与视图
- **WHEN** 用户选择一个已授权的 MySQL 关系库连接并展开库表视图列表
- **THEN** 系统返回该连接目标库下的表与视图清单，并为每个对象标注其类型为表或视图

#### Scenario: 枚举 PostgreSQL 连接并过滤系统 schema
- **WHEN** 用户选择一个已授权的 PostgreSQL 关系库连接并展开库表视图列表
- **THEN** 系统返回用户 schema 下的表与视图清单，且结果中不包含 `pg_catalog` 与 `information_schema` 等系统 schema 的对象

#### Scenario: 枚举按 schema 收窄
- **WHEN** 连接存在多个用户 schema 且用户指定其中一个 schema 后刷新列表
- **THEN** 系统仅返回该 schema 下的表与视图，并同时给出该连接可选的 schema 清单

#### Scenario: 拒绝越权枚举
- **WHEN** 请求方所属项目与连接所属项目不一致时发起库表枚举
- **THEN** 系统拒绝该请求并返回无该项目访问权限，不返回任何对象清单

#### Scenario: 枚举仅执行只读系统目录查询
- **WHEN** 用户枚举库表与视图
- **THEN** 系统不向目标库发送任何写入、DDL 或其他 DML 语句

### Requirement: 查询工作台四区布局
系统 SHALL 在只读查询页以四区布局呈现关系库查询能力：左列上方为数据连接选择器，左列下方为当前连接的表与视图列表，右列上方为 SQL 编辑器与执行操作，右列下方为查询结果预览区。

#### Scenario: 左列选择连接并查看库表
- **WHEN** 用户打开只读查询页
- **THEN** 左列上方展示可选择的数据连接，左列下方展示当前所选连接的表与视图列表

#### Scenario: 切换连接刷新库表列表
- **WHEN** 用户在左列切换为另一个关系库连接
- **THEN** 左列下方的表与视图列表刷新为该连接的对象清单，不再展示前一连接的对象

#### Scenario: 未选择连接时的引导
- **WHEN** 用户尚未选择数据连接或系统无可用的关系库连接
- **THEN** 系统在库表视图列表区给出明确提示，且不发起枚举请求

#### Scenario: 查询结果在右下方预览区呈现
- **WHEN** 用户在右上方 SQL 编辑器提交查询并执行成功
- **THEN** 右下方结果预览区以列名表头与按列顺序对应的真实值渲染结果行

### Requirement: 点击表名预填只读查询语句
系统 SHALL 在用户点击表与视图列表中的任一对象时，向 SQL 编辑器写入一条针对该对象的基础只读查询语句；该语句 SHALL 使用 schema 限定的对象名并包含行数上限；系统 SHALL 仅预填而不自动执行查询。

#### Scenario: 点击表名生成基础查询语句
- **WHEN** 用户点击列表中的表 `orders`
- **THEN** SQL 编辑器的内容被替换为一条以限定标识符引用 `orders` 且带行数上限的 `SELECT` 语句

#### Scenario: 点击表名不触发查询执行
- **WHEN** 用户点击列表中的表名或视图名
- **THEN** 系统不向查询接口发起请求，仅更新 SQL 编辑器内容

#### Scenario: 预填后由用户改写并执行
- **WHEN** 用户在预填语句基础上增加 `WHERE` 条件后点击执行
- **THEN** 系统按既有只读守卫（单条 SELECT、拒绝写与多语句、行数上限与超时）执行该语句并返回结果

#### Scenario: 标识符按目标库方言安全引用
- **WHEN** 被点击对象的名称包含大写字母或特殊字符
- **THEN** 系统按该连接所属数据库的方言对该标识符做引用，生成的语句可直接执行

### Requirement: 库表视图列表的检索与类型过滤
系统 SHALL 支持按名称关键字过滤表与视图列表，并 SHALL 支持在「表」与「视图」之间切换显示范围。

#### Scenario: 关键字过滤列表
- **WHEN** 用户在列表上方的检索框输入关键字
- **THEN** 列表仅展示名称包含该关键字的表与视图

#### Scenario: 按对象类型过滤
- **WHEN** 用户将对象类型切换为仅表或仅视图
- **THEN** 列表仅展示所选类型的对象，切换回全部时恢复展示两类对象
