## Purpose

定义多用户、角色、项目与命名空间隔离、外部触发 API 凭据（服务账号）与操作审计日志能力，保障多租户下的权限控制与可追溯性。

## Requirements

### Requirement: 多用户与角色
系统 SHALL 支持多用户及角色，角色包括管理员、开发者、只读。

#### Scenario: 角色授权
- **WHEN** 管理员为用户分配角色
- **THEN** 系统按角色控制用户可执行的操作

#### Scenario: 角色操作边界
- **WHEN** 只读用户尝试发布任务、修改配置或回滚版本
- **THEN** 系统拒绝操作；只读用户仅可浏览任务、配置与运行信息

### Requirement: 项目与命名空间隔离
系统 SHALL 支持项目或命名空间隔离，用户仅能访问其授权范围内的资源。

#### Scenario: 跨项目隔离
- **WHEN** 用户访问非授权项目的连接、任务或数据
- **THEN** 系统拒绝访问并保证数据隔离

### Requirement: 外部触发 API 凭据
系统 SHALL 支持为外部系统签发 API 凭据（服务账号），凭据绑定单一项目范围、仅具备任务触发权限，并可由管理员随时吊销。

#### Scenario: 凭据签发与使用
- **WHEN** 管理员为某项目签发 API 凭据
- **THEN** 该凭据仅可触发该项目内任务，凭据明文仅在签发时展示一次，后续仅存引用与摘要

#### Scenario: 吊销凭据
- **WHEN** 管理员吊销某 API 凭据
- **THEN** 使用该凭据的后续触发请求立即被拒绝

### Requirement: 操作审计日志
系统 SHALL 记录操作审计日志，覆盖配置变更、任务触发（含外部 API 触发）、数据查询与凭据管理。

#### Scenario: 审计留痕
- **WHEN** 用户执行配置、触发、查询或凭据管理操作
- **THEN** 系统记录操作者、时间、项目与操作内容供审计

### Requirement: 默认账号与账号收敛
系统 SHALL 在首次启动/安装时仅创建一个 `admin` 管理员账号、不创建演示或开发者账号；并在数据清理后使系统账号收敛为仅保留一个角色为管理员的账号。

#### Scenario: 首次启动账号
- **WHEN** 系统在空数据目录上首次启动
- **THEN** 系统仅存在一个名为 `admin` 且角色为管理员（admin）的账号

#### Scenario: 无演示账号
- **WHEN** 用户查看当前账号列表
- **THEN** 列表不包含演示/开发者占位账号（如 `dev`），仅含 `admin` 及其之后显式创建的用户

#### Scenario: 清理后账号收敛
- **WHEN** 执行清理并将系统账号收敛为单一管理员
- **THEN** 用户列表中仅剩角色为管理员的一个账号，其余账号均被移除

### Requirement: LLM 配置管理员专属
系统 SHALL 仅允许管理员角色读写 LLM 配置；非管理员访问配置读写接口返回 403。对话式建任务仍沿用开发者角色权限（与任务保存一致）。

#### Scenario: 管理员读写配置
- **WHEN** 管理员访问 LLM 配置的查询、保存、测试或吊销接口
- **THEN** 操作正常执行并返回对应结果

#### Scenario: 非管理员被拒
- **WHEN** 开发者或只读角色访问 LLM 配置读写接口
- **THEN** 系统返回 403，配置内容与明文凭据不可见
